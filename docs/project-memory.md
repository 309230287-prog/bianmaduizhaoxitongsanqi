# 项目记忆 - 商品编码对照二期

- 更新时间：2026-04-18
- 当前阶段：二期基础编码已开始，金样本、模型契约、Excel 读取和候选池评估已形成
- 当前主线：大模型主导的商品语义翻译与证据对齐

## 1. 当前项目定位

本项目二期不再沿用一期商品匹配产品逻辑。

一期产品判断为失败产品，只作为历史教训和少量工具性能力参考。

二期重新定义为：

**大模型主导的商品语义翻译与证据对齐系统。**

核心分工：

**大模型负责理解和判断，程序负责流程和留痕。**

## 2. 当前核心共识

- 二期不是“找最像商品”。
- 二期不是“字段拆解系统”。
- 二期不是在一期匹配流程上继续修补。
- 二期要解决的是“客户商品语言”到“我司商品语言”的翻译。
- 客户商品记录应被当作整行语义单元。
- 我司商品名称和描述同样需要被理解，不是天然纯净标准答案。
- 翻译正确指业务商品身份一致，不是单个字段相同。
- 自动落码不能只看模型置信度。
- 差异可能影响商品身份、价格、单位、包装或结算时，不应自动落码。
- 差异只是表达差异且有稳定业务等价关系时，可以弱自动落码，但必须留痕。

## 4. 当前建议技术路线

推荐技术栈：

- Python 3.11+
- FastAPI
- Pydantic
- openpyxl
- SQLite
- httpx
- Jinja2 或轻量前端

推荐产品形态：

```text
本地 Web 工具
-> Excel 导入
-> 字段整理
-> 候选池生成
-> 大模型语义翻译
-> 证据对齐与风险分级
-> 人工审核
-> 历史关系沉淀
-> Excel 导出
```

## 5. 当前关键技术参数

- 黄金样本数量：先做 30 条
- 扩展样本数量：100 到 200 条
- 默认候选数：10
- 最大候选数：20
- 模型调用：先两段式，后续可验证是否合并
- temperature：0 到 0.2
- 单次请求超时：60 秒
- 最大重试次数：2
- 验证阶段并发：1 到 3
- 原型阶段默认并发：3
- Top10 候选覆盖率目标：不低于 90%
- Top20 候选覆盖率目标：不低于 95%
- 强自动落码错误率：目标 0，最高不超过 1%
- 弱自动落码错误率：不超过 2%
