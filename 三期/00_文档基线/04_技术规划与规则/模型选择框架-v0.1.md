# 模型选择框架 v0.1

- 日期：2026-04-18
- 阶段：二期模型试跑前置框架

## 1. 目标

先搭模型选择底层框架，再做 IDE 风格界面。

当前目标不是做漂亮 UI，而是把以下概念固定下来：

- Provider：模型提供方，例如阿里云百炼、OpenAI Compatible。
- Model Option：可选模型，例如 `qwen-plus`、百炼自定义模型、第三方兼容模型。
- Selection ID：模型选择器使用的稳定 ID，例如 `auto:recommended`、`bailian:qwen-plus`。
- Runtime Settings：真正调用模型时需要的 `base_url`、`production_model_name`、`api_key`、超时和重试。

## 2. 当前代码入口

- 模型目录：`src/product_matcher/services/model_catalog.py`
- 配置管理：`src/product_matcher/services/model_settings.py`
- 配置样例：`config/model_settings.example.json`

## 3. 当前模型选择项

- `auto:recommended`
  - 当前映射到阿里云百炼 `qwen-plus`。
  - 后续可扩展为根据任务自动选择模型。

- `bailian:qwen-plus`
  - 当前推荐生产模型。
  - 默认 Base URL：`https://dashscope.aliyuncs.com/compatible-mode/v1`
  - 默认环境变量：`DASHSCOPE_API_KEY`

- `bailian:custom`
  - 使用阿里云百炼兼容接口，但允许手动填写模型名。

- `custom:openai-compatible`
  - 用于第三方或本地 OpenAI-compatible `/chat/completions` 接口。

## 4. 兼容策略

现有页面暂时还没有真正的 IDE 风格模型选择器。

因此 `build_settings_from_form()` 支持两种输入：

- 新输入：表单带 `model_selection_id`，按模型目录自动套用 provider、Base URL、模型名和默认环境变量。
- 旧输入：表单不带 `model_selection_id`，继续尊重用户手动填写的 provider、Base URL 和模型名。

这保证了框架先落地，但不破坏现有配置页。

## 5. 后续 UI 接入方式

后续页面不应该自己硬编码模型列表。

页面应从：

```python
describe_model_settings(settings)["model_picker_groups"]
```

读取模型选择器分组。

这样 UI 可以做成类似 IDE 的模型选择器，但模型目录仍由后端统一维护。

## 6. 暂不做

- 暂不做多模型自动路由。
- 暂不做备用模型降级。
- 暂不做 UI 视觉改造。
- 暂不把模型选择和商品匹配逻辑混在一起。
