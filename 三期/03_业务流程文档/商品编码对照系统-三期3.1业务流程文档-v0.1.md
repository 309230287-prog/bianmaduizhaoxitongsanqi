# 商品编码对照系统 - 三期 3.1 业务流程文档 v0.1

- 日期：2026-04-25
- 阶段：三期 3.1 主线闭环
- 文档性质：业务流程文档，不是 UI 设计稿，不是技术方案
- 对应需求文档：`商品编码对照系统-三期需求文档-v0.2.md`

## 1. 文档目的

本文档用于说明三期 3.1 阶段用户如何完成一轮商品编码对照。

3.1 的目标不是一次性做完整系统。

3.1 的目标是先跑通主线闭环：

**初始化配置 -> 导入商品库 -> 确认字段 -> 生成候选 -> 查看解释 -> 人工确认 -> 导出结果。**

本文档重点回答：

- 用户打开系统后先看到什么
- 首次使用时如何完成初始化配置
- 日常使用时如何进入业务流程
- 每一步用户做什么
- 每一步系统做什么
- 每一步失败时怎么提示
- 每一步产出什么

## 2. 3.1 流程总览

三期 3.1 分成两条流程。

### A. 首次启动和初始化配置流程

适用场景：

- 第一次打开系统
- 模型配置缺失
- API Key 缺失或失效
- 默认目录不存在
- 中文路径或文件名支持异常
- 用户主动进入设置页修改配置

目标：

**确保系统具备进行商品对照的基础配置，并让用户明确知道当前哪些能力可用。**

### B. 日常商品编码对照流程

适用场景：

- 系统配置正常
- 用户要处理一份客户商品库
- 用户要手工查询单条客户商品

目标：

**完成一轮真实商品编码对照，并导出业务人员能看懂的结果表。**

## 3. 首页入口流程

### 3.1 用户看到什么

用户打开系统后，应先进入首页工作台。

首页应清楚展示：

- 系统名称：商品编码对照系统
- 当前配置状态
- 当前模型状态
- 我司商品库状态
- 最近一次任务
- 主要操作入口

主要操作入口包括：

- 开始商品对照
- 更新我司商品库
- 上传客户商品库
- 手工输入商品
- 查看历史任务
- 系统设置

### 3.2 系统自动检查什么

系统打开时自动检查：

- 是否存在基础配置
- 模型服务是否启用
- API Key 是否已配置
- 当前模型名称是否存在
- 默认数据目录是否可用
- 默认导出目录是否可用
- 日志目录是否可用
- 中文文件名和中文路径是否可用
- 是否已有我司商品库

### 3.3 首页状态提示

首页应使用中文状态提示。

示例：

- 配置正常，可以开始商品对照
- 模型未配置，无法进行智能候选和解释
- 尚未导入我司商品库，请先导入
- 默认导出目录不可用，请到设置中修正
- API Key 未配置，请先完成模型设置

### 3.4 首页分流规则

如果配置正常：

- 用户可以直接进入日常商品编码对照流程。

如果配置缺失或异常：

- 系统应提示用户进入初始化配置流程。
- 系统不应悄悄进入模型判断流程。

如果只是模型未配置：

- 系统应明确提示智能候选、中文解释等能力不可用。
- 第一版是否允许无模型继续走基础流程，由后续技术方案决定。
- 在 3.1 流程文档中，默认按“模型未配置则不能进行智能对照”处理。

## 4. A 流程：首次启动和初始化配置

### A1. 进入初始化配置页

触发方式：

- 首次打开系统自动进入
- 首页提示配置异常后点击进入
- 用户主动点击系统设置

用户看到：

- 当前配置总览
- 哪些配置已完成
- 哪些配置缺失
- 下一步应配置什么

系统显示：

- 模型配置状态
- 数据目录状态
- 导出目录状态
- 日志目录状态
- 中文路径检查状态

产出：

- 初始化配置检查结果

### A2. 配置模型服务

用户需要配置：

- 是否启用模型服务
- 模型提供方
- Base URL
- API Key 来源或录入方式
- 模型名称
- 请求超时
- 失败重试次数

系统要求：

- API Key 不能写入源码。
- API Key 不能提交到仓库。
- API Key 显示时应脱敏。
- 配置保存后应提示保存成功或失败。

系统检查：

- Base URL 是否为空
- API Key 是否为空
- 模型名称是否为空
- 配置格式是否明显错误

异常提示：

- API Key 未填写
- Base URL 未填写
- 模型名称未填写
- 配置保存失败
- 模型连接测试失败

产出：

- 模型配置记录
- 模型可用性状态

### A3. 测试模型连接

用户操作：

- 点击测试连接

系统操作：

- 使用当前配置发起最小测试请求
- 返回连接是否成功
- 显示失败原因

成功提示：

- 模型连接成功，可以进行智能对照

失败提示：

- 模型连接失败，请检查 API Key、Base URL 或网络

注意：

- 测试连接不应发送客户商品库真实数据。
- 测试连接只验证模型服务是否可用。

产出：

- 模型连接测试结果

### A4. 配置默认目录

用户需要确认：

- 默认数据目录
- 默认导出目录
- 日志保存目录

系统检查：

- 目录是否存在
- 是否可读
- 是否可写
- 是否支持中文路径

异常提示：

- 目录不存在
- 目录不可写
- 中文路径测试失败

产出：

- 默认目录配置
- 目录可用性状态

### A5. 初始化完成

完成条件：

- 必要模型配置已填写
- 模型连接测试通过
- 默认目录可用
- 中文路径检查通过

系统提示：

- 初始化完成，可以开始商品对照

用户下一步：

- 返回首页
- 进入日常商品编码对照流程

## 5. B 流程：日常商品编码对照

### B1. 选择业务入口

用户从首页选择：

- 上传客户商品库
- 手工输入商品
- 更新我司商品库

系统前置检查：

- 配置是否有效
- 模型是否可用
- 是否已有我司商品库

如果没有我司商品库：

- 系统提示先导入我司商品库。

如果模型不可用：

- 系统提示智能对照不可用。

### B2. 导入或更新我司商品库

适用场景：

- 第一次使用
- 我司商品库发生更新
- 用户主动替换我司商品库

用户操作：

- 选择我司商品库 Excel
- 上传或导入

系统读取：

- 工作表名称
- 表头
- 样例行
- 数据行数
- 重复列
- 空白列

系统提示：

- 导入成功
- 发现重复列
- 发现空白列
- 缺少我司商品编码
- 缺少我司商品名称

用户确认：

- 哪一列是我司商品编码
- 哪一列是我司商品名称
- 哪些列是品牌、规格、单位、分类、别名、描述
- 哪些列不参与判断

产出：

- 我司商品库记录
- 我司字段含义确认结果

### B3. 上传客户商品库

用户操作：

- 选择客户商品库 Excel
- 上传或导入

系统读取：

- 工作表名称
- 表头
- 样例行
- 数据行数
- 重复列
- 空白列
- 明显异常字段

系统提示：

- 导入成功
- 发现重复商品名称列
- 发现空白列
- 商品名称字段未确认
- 规格字段缺失，可能影响包装和容量判断
- 单位字段缺失，可能影响结算单位判断

用户确认：

- 商品名称字段
- 客户编号字段
- 品牌字段
- 规格字段
- 单位字段
- 类别字段
- 备注字段
- 其他补充字段
- 不参与判断字段

产出：

- 客户商品库记录
- 客户字段含义确认结果

### B4. 手工输入单条客户商品

适用场景：

- 用户临时查询一条商品
- 用户没有完整客户 Excel
- 用户想测试某条商品对照

用户输入：

- 商品名称
- 品牌
- 规格
- 单位
- 类别
- 备注
- 客户编号
- 其他补充信息

最低要求：

- 商品名称不能为空

系统处理：

- 将手工输入视为一条客户商品记录
- 进入同一套候选生成和证据对齐流程

产出：

- 单条客户商品记录

### B5. 字段确认完成检查

系统检查：

- 客户商品名称是否确认
- 我司商品编码是否确认
- 我司商品名称是否确认
- 强建议字段是否缺失

如果必需字段缺失：

- 系统阻止继续，并提示必须补齐。

如果强建议字段缺失：

- 系统允许继续，但提示会影响自动落码等级。

产出：

- 字段确认通过或失败

### B6. 生成候选

用户操作：

- 点击开始对照

系统操作：

- 读取客户商品记录
- 读取我司商品库
- 根据客户整行信息生成我司候选
- 为每条客户商品保留候选来源说明

候选来源可能包括：

- 名称相似
- 核心品名一致
- 品牌一致
- 规格一致
- 单位一致
- 分类接近
- 历史确认
- 业务等价
- 人工曾经选择

异常情况：

- 没有候选
- 候选过多
- 候选都存在核心冲突

产出：

- 每条客户商品的候选列表
- 候选来源摘要

### B7. 证据对齐和中文解释

系统对客户记录和候选进行证据对齐。

系统输出：

- 推荐我司商品
- 备选候选
- 对上的信息
- 没对上的信息
- 风险提示
- 推荐理由
- 五档状态

五档状态包括：

- 自动落码
- 自动落码但有表达差异
- 建议落码待确认
- 必须人工审核
- 未找到可靠匹配

系统原则：

- 不能只输出一个编码。
- 不能把必须人工审核伪装成自动落码。
- 不能把未找到可靠匹配伪装成确定编码。

产出：

- 对照结果草稿

### B8. 结果查看

用户看到：

- 客户原始商品
- 推荐我司商品
- 备选候选
- 对照状态
- 推荐理由
- 风险提示
- 是否需要人工审核

用户可以筛选：

- 全部结果
- 自动落码
- 自动落码但有表达差异
- 建议落码待确认
- 必须人工审核
- 未找到可靠匹配

产出：

- 用户待审核列表

### B9. 人工审核

用户可以对每条结果进行：

- 确认推荐结果
- 改选其他候选
- 标记无匹配
- 修改结果状态
- 填写审核备注
- 标记系统理解错误
- 标记遗漏信息

系统记录：

- 人工确认结果
- 审核备注
- 审核时间
- 审核来源

第一版记忆边界：

- 人工确认可以保存。
- 记忆先记录，不直接控制自动落码。
- 历史确认可以作为后续参考。

产出：

- 审核后的对照结果
- 人工确认记录

### B10. 导出结果

用户操作：

- 点击导出结果
- 选择导出位置

系统操作：

- 基于客户原始 Excel 生成新文件
- 不覆盖原文件
- 保留客户原始所有列
- 尽量保持客户原始列顺序和行顺序
- 在客户原始列后面追加中文结果列
- 不应导出一张只包含结果字段的新表

追加结果列建议包括：

- 对照状态
- 我司商品编码
- 我司商品名称
- 我司品牌
- 我司规格
- 我司单位
- 推荐理由
- 证据对齐摘要
- 风险提示
- 备选候选
- 是否需要人工审核
- 人工确认结果
- 人工审核备注

异常提示：

- 导出目录不可写
- 文件被占用
- 导出失败

产出：

- 编码对照结果 Excel

## 6. 异常和中断流程

### 6.1 模型不可用

触发场景：

- API Key 缺失
- API Key 失效
- Base URL 错误
- 网络不可用
- 模型服务超时

系统处理：

- 明确提示模型不可用。
- 不应静默生成模型结果。
- 不应伪造智能判断。
- 引导用户进入设置页修正。

### 6.2 文件读取失败

触发场景：

- Excel 文件损坏
- 文件格式不支持
- 文件被占用
- 表头无法识别

系统处理：

- 明确提示读取失败原因。
- 不应生成空任务。

### 6.3 字段确认不完整

触发场景：

- 客户商品名称未确认
- 我司商品编码未确认
- 我司商品名称未确认

系统处理：

- 阻止继续对照。
- 提示必须补齐字段。

### 6.4 导出失败

触发场景：

- 导出目录不存在
- 导出目录不可写
- 文件被占用

系统处理：

- 提示失败原因。
- 允许用户重新选择导出目录。

## 7. 3.1 不做什么

3.1 不做：

- 完整记忆系统
- 复杂审核流
- 多人协同
- 权限体系
- 高级统计
- 大规模自动学习
- 模型精调
- 复杂模型管理中心
- 让记忆直接决定自动落码

3.1 只做：

**把主线跑通。**

## 8. 3.1 验收标准

3.1 至少应满足：

- 首次打开能看到配置状态。
- 配置缺失时能引导用户完成初始化。
- 配置正常时能进入首页工作台。
- 能导入我司商品库。
- 能导入客户商品库。
- 能手工输入单条客户商品。
- 能完成字段含义确认。
- 必需字段缺失时能阻止继续。
- 强建议字段缺失时能给出风险提示。
- 能生成候选或说明无候选原因。
- 能输出中文解释和风险提示。
- 能输出五档中文状态。
- 能进行人工确认、修改、标记无匹配。
- 能导出编码对照结果 Excel。
- 不覆盖原始 Excel。
- 模型不可用时不伪造智能结果。
