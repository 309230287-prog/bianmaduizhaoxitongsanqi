# 商品编码对照系统 - 三期 3.1 DEMO 评审修改文档 v0.1

- 日期：2026-04-25
- 文档性质：DEMO 评审修改记录
- 当前阶段：三期 3.1 主线收缩和界面流程修正
- 适用范围：后续统一修改低保真原型、业务流程文档、需求文档和技术方案

## 1. 本次评审结论

本次 DEMO 评审后，三期 3.1 的方向进一步收缩。

3.1 不做完整页面审核工作台。

3.1 先做：

**导入数据 -> 确认字段 -> 跑完一轮 -> 看运行统计 -> 导出可人工处理的 Excel -> 人工加工后进入下一轮。**

页面先服务于任务创建和运行状态。

明细解释、人工审核和修正，第一版主要通过导出的 Excel 承接。

后续版本再把 Excel 中的人工审核和候选解释逐步搬回系统界面。

## 2. 3.1 页面主线调整

### 2.1 调整前的问题

当前 DEMO 中存在以下问题：

- 客户库上传、字段确认、开始对照被拆成多个页面，业务上显得割裂。
- 点击“开始第一轮对照”后，页面更像说明页，不像真实任务运行页。
- “候选解释”和“人工审核”页面对 3.1 来说过重，容易把第一版拖成完整审核工作台。
- 如果在页面做明细表，会牵出分页、筛选、排序、候选展开、人工确认、修改保存等复杂能力。

### 2.2 调整后的主线

3.1 页面主线调整为：

**首页 -> 初始化配置 -> 更新我司商品库 -> 新建对照任务 -> 对照进度看板 -> 导出 Excel。**

其中：

- 我司商品库更新独立成系统基础资料管理，不放进每次客户任务流程。
- 客户商品库上传、手工输入、字段确认、开始第一轮对照，合并到“新建对照任务”页面。
- 点击“开始第一轮对照”后，进入“对照进度看板”。
- 候选解释和人工审核页面先不进入 3.1 主线。

## 3. 新建对照任务页面

“新建对照任务”页面内部保留三个步骤，但用户感知上是同一个页面。

### 3.1 第一步：导入客户数据

支持两种入口：

- 上传客户商品库 Excel。
- 手工输入单条客户商品。

上传客户库后，本页只展示：

- 客户 Excel 中读到的列名。
- 每列样例。
- 系统初步提醒，例如重复列名、空白列、疑似商品名称列、疑似规格列。

本页不要求用户做复杂字段判断。

系统可以预判字段含义，但不能完全黑箱跳过人工确认。

### 3.2 第二步：确认关键字段

系统展示自己的预判结果。

用户只确认关键字段是否正确。

关键字段包括：

- 客户商品名称。
- 规格。
- 单位。
- 备注或补充信息。

第一版不要让用户处理过多字段细节。

必须字段未确认时，不允许开始对照。

强建议字段有问题时，允许继续，但要降低自动落码安全等级。

### 3.3 第三步：开始第一轮对照

字段确认通过后，显示“开始第一轮对照”按钮。

点击后不直接跳候选解释。

点击后进入“对照进度看板”。

## 4. 对照进度看板

“对照进度看板”是点击“开始第一轮对照”之后的核心页面。

它回答：

- 当前跑的是第几轮。
- 数据规模是多少。
- 已经跑到哪里。
- 第一轮结果大概分布如何。
- 是否可以导出 Excel。

### 4.1 看板基础信息

页面顶部应展示：

- 当前任务名称。
- 当前轮次，例如第 1 轮、第 2 轮。
- 当前状态，例如运行中、已暂停、已停止、本轮已完成。
- 当前使用的我司商品库版本或更新时间。

### 4.2 看板数字框

看板中间展示几个统计数字框。

建议包含：

- 我司商品库总数。
- 客户商品库总数。
- 已完成数量。
- 自动落码无风险数量。
- 建议落码需复核数量。
- 必须人工干预数量。
- 未找到可靠匹配数量。

这些数字可以动态变化。

DEMO 中可以用滚动数字表达“系统正在跑”。

### 4.3 进度条

底部保留进度条。

进度条下方显示当前处理进度，例如：

`正在处理：第 1600 / 2581 条。`

进度条是本页重要元素，应保留。

### 4.4 任务控制按钮

看板需要三个运行控制按钮：

- 暂停。
- 继续。
- 停止。

暂停含义：

- 当前任务先停住。
- 不再继续处理剩余商品。
- 已完成结果保留。

继续含义：

- 从暂停位置继续跑。

停止含义：

- 取消本轮任务。
- 本轮不算完整完成。
- 不允许导出正式结果。

### 4.5 导出按钮

看板底部放“导出 Excel”按钮。

导出按钮规则：

- 运行中不能点击。
- 暂停中不能点击正式导出。
- 停止后不能导出正式结果。
- 只有“本轮已完成”后才能点击。

如果本轮结果中仍有需复核或人工干预，也可以导出。

但导出的 Excel 必须清楚标注：

- 哪些是自动落码无风险。
- 哪些是建议落码需复核。
- 哪些必须人工干预。
- 哪些未找到可靠匹配。

系统不能把需复核或人工干预的结果伪装成已确认编码。

## 5. 3.1 暂不做页面明细表

本次评审确认：

**3.1 暂不做点击数字框进入页面明细表。**

原因：

- 页面明细表会引入分页、筛选、排序、候选展开等功能。
- 一旦能看明细，就很自然会要求页面里人工确认、改选和保存。
- 这会把 3.1 从主线闭环拖成完整审核工作台。

3.1 的数字框只作为统计展示。

明细结果通过 Excel 导出承接。

后续版本再做页面明细和审核工作台。

## 6. 候选解释和人工审核页面后置

当前 DEMO 中的“候选解释”和“人工审核”页面，在 3.1 阶段先不作为主线页面。

候选解释不是不要。

候选解释先进入导出 Excel。

人工审核也不是不要。

人工审核先在导出 Excel 中完成。

后续版本再把这些能力产品化到系统界面中。

3.1 的主线目标是：

**跑完一轮，导出业务能处理的 Excel。**

## 7. 导出 Excel 设计

为了避免一张表过宽，3.1 导出的 Excel 应采用多工作表结构。

### 7.1 工作表一：对照结果总表

对照结果总表面向业务人员日常处理。

要求：

- 保留客户原始列。
- 保留客户原始行顺序。
- 在客户原始列后追加少量关键结果列。

建议追加列：

- 系统任务行ID。
- 原始行号。
- 对照状态。
- 我司商品编码。
- 我司商品名称。
- 是否需要人工审核。
- 推荐理由简述。
- 风险提示简述。
- 查看详细证据。
- 人工确认结果。
- 人工审核备注。

### 7.2 工作表二：详细证据表

详细证据表用于查看原因和追溯。

建议包含：

- 系统任务行ID。
- 原始行号。
- 客户商品名称。
- 推荐我司商品。
- 证据对齐摘要。
- 对上的信息。
- 没对上的信息。
- 风险详情。
- 备选候选 1。
- 备选候选 2。
- 备选候选 3。
- 返回总表。

### 7.3 工作表三：统计汇总表

统计汇总表用于查看本轮整体结果。

建议包含：

- 当前任务名称。
- 当前轮次。
- 我司商品库总数。
- 客户商品库总数。
- 已完成数量。
- 自动落码无风险数量。
- 建议落码需复核数量。
- 必须人工干预数量。
- 未找到可靠匹配数量。
- 本轮开始时间。
- 本轮完成时间。
- 使用模型。
- 我司商品库版本或更新时间。

### 7.4 Excel 内部链接

Excel 支持内部超链接。

3.1 应支持：

- 总表中“查看详细证据”点击后跳到详细证据表对应行。
- 详细证据表中“返回总表”点击后跳回总表对应行。
- 统计汇总表中统计分类可选地链接到详细证据表对应区域。

实现层面可以使用 `openpyxl` 写入内部超链接。

### 7.5 必须保留系统任务行ID

导出 Excel 必须包含系统任务行ID。

原因：

- 人工加工 Excel 后，系统需要知道每一行对应原客户库的哪一条记录。
- 第二轮导入人工加工后的 Excel 时，需要靠任务行ID追溯。
- 如果没有任务行ID，人工排序、筛选、修改后系统会难以回接。

任务行ID不应由业务人员手工维护。

系统生成并保留即可。

## 8. 人工加工和第二轮闭环

第一轮导出 Excel 后，业务人员会在 Excel 中人工处理。

人工可能做：

- 确认系统推荐结果。
- 修改我司商品编码。
- 标记无匹配。
- 标记需要新增我司商品。
- 填写人工审核备注。

如果发现我司商品库缺商品，应先补全我司商品库。

之后在系统里更新我司商品库。

### 8.1 第二轮入口

首页需要有入口：

**继续历史任务 / 开始下一轮。**

进入后，用户上传：

- 第一轮人工加工后的 Excel。
- 如有变化，先更新后的我司商品库。

然后点击：

**开始第 2 轮对照。**

### 8.2 第二轮处理规则

第二轮不是从零开始。

第二轮应基于：

- 原客户库。
- 第一轮系统结果。
- 人工加工结果。
- 更新后的我司商品库。

第二轮规则：

- 人工已确认的，不要被系统随意覆盖。
- 人工指定我司编码的，系统要校验编码是否存在于最新我司库。
- 第一轮未匹配或需新增的，如果我司库更新后已有对应商品，应重新对照。
- 仍然无法确认的，继续输出为建议复核、必须人工干预或未找到可靠匹配。
- 如果人工结果和当前我司库冲突，应提示风险，不应静默接受。

## 9. 后续版本边界

3.1 不做：

- 页面明细列表。
- 页面候选展开。
- 页面人工确认。
- 页面改选候选。
- 完整审核工作台。
- 多人协同审核。
- 复杂记忆系统。

后续版本再做：

- 点击统计框查看页面明细。
- 页面内候选解释。
- 页面内人工审核和改选。
- 审核结果保存。
- 审核记忆沉淀。
- 更完整的历史任务管理。
