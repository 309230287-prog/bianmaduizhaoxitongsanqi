# 商品编码对照系统三期3.1 Implementation Plan

> **For agentic workers:** REQUIRED: Use $subagent-driven-development (if subagents available) or $executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 落地三期 3.1 最小可用桌面工作台，按 003 号系统模型流程方案跑通“导入我司库 -> 导入客户库 -> 模型发令多轮入圈 -> 候选检索 -> 自动落码安全门 -> 运行看板 -> Excel 导出 -> 下一轮回导”的主线。

**Architecture:** 先实现纯 Python 业务引擎和测试样本，证明 003 流程能独立跑通；再用 FastAPI 包装成本地服务；最后接 Web 前端和 Tauri 桌面壳。系统只做执行、记录和安全校验，模型通过结构化命令主导语义分批。

**Tech Stack:** Python 3.11+、pytest、FastAPI、SQLite、openpyxl、httpx、Vite + React + TypeScript、Tauri。

---

## 0. 执行原则

- 三期从干净工程开始，不继承一期代码和旧二期交付代码。
- 允许参考三期文档、原型和真实 Excel 文件。
- 所有生产代码必须先有失败测试。
- 所有模型输出必须被结构化校验。
- 所有自动落码必须经过 `AutoCodeGate`。
- 003 号方案是当前模型流程准绳。
- 先做可测试业务引擎，再做界面。

## 2. 核心模块职责

| 模块 | 职责 |
|---|---|
| `domain/models.py` | 商品、候选、任务行、运行结果等基础数据结构 |
| `knowledge/lexicon.py` | 别名和同义词分级，不做复杂规则库 |
| `planning/round_command.py` | 003 模型发令 JSON 结构和校验 |
| `planning/round_planner.py` | 调用模型或测试替身，生成本轮结构化命令 |
| `pool/nature_pool.py` | 大自然池、回流次数、疑难池 |
| `candidates/executor.py` | 按模型命令执行候选检索 |
| `matching/comparator.py` | 调用模型比较客户商品和候选 |
| `matching/auto_code_gate.py` | 自动落码机器安全门 |
| `runs/engine.py` | 串起一轮任务主流程 |
| `runs/audit_trail.py` | 证据链和过程追溯 |
| `runs/metrics.py` | 运行统计 |
| `excel/importer.py` | Excel 导入 |
| `excel/exporter.py` | 多工作表 Excel 导出 |
| `api/app.py` | FastAPI 本地服务入口 |

## 自审修订要求 v0.1

本节是对执行计划的反向审查结果。

结论：

**原计划可以作为主干，但不能直接执行到底。必须补齐以下阻塞项，否则 3.1 会出现“业务引擎能测、真实产品不能用”的断层。**

### A. 阻塞问题 1：缺少真实 DeepSeek API 接入任务

原计划有 `FakeModelClient`，这是正确的，因为先用测试替身稳定接口。

但原计划没有明确真实 DeepSeek API 接入任务。

如果不补：

- 后端测试能过，但真实模型不可用。
- 用户配置了 Key 也无法真正跑模型。
- 003 的“模型发令”会停留在假模型阶段。

必须补充任务：

**Task 8A：实现 DeepSeekModelClient。**

要求：

- 不把 API Key 写入代码。
- 支持从配置或环境变量读取 Key。
- 支持 Base URL 和模型名称配置。
- 请求和返回必须转成内部结构。
- 模型返回 JSON 解析失败时，必须降级，不得自动落码。
- 单元测试使用 mocked httpx，不直接打真实 API。

建议测试：

```python
def test_deepseek_client_rejects_malformed_json_response():
    client = DeepSeekModelClient(http_client=FakeHttpClient(response_text="不是JSON"))

    result = client.plan_round({"sample_terms": ["生抽"]})

    assert result.is_error
```

### B. 阻塞问题 2：缺少模型配置和 API Key 管理任务

原计划前端写了“配置模型”，但后端没有对应配置存储和校验任务。

如果不补：

- Web 界面即使做了输入框，也没有稳定后端承接。
- API Key 可能被错误写入源码、日志或导出文件。

必须补充任务：

**Task 12A：实现模型配置接口和安全保存策略。**

要求：

- API Key 不进入 Git。
- API Key 默认不写入普通日志。
- 开发期允许使用环境变量。
- 正式桌面版优先使用本机安全凭据存储。
- `/settings/model/test` 必须能测试连接并返回中文结果。

### C. 阻塞问题 3：缺少 SQLite 持久化任务

技术栈写了 SQLite，但任务中没有持久化实现。

如果不补：

- 任务刷新后丢失。
- 暂停、继续、停止无法可靠恢复。
- 第二轮回导缺少任务行 ID 和历史状态。

必须补充任务：

**Task 12B：实现 SQLite 数据库和仓储层。**

最小表：

- `company_products`
- `match_tasks`
- `task_rows`
- `task_runs`
- `run_results`
- `round_commands`
- `audit_entries`
- `settings`

第一版不追求复杂 ORM，可以先用标准库 `sqlite3` 或轻量封装。

### D. 阻塞问题 4：缺少字段确认后端任务

原计划有 Excel 导入，但没有“字段含义确认”的后端结构。

如果不补：

- 系统不知道客户哪一列是商品名称、规格、单位、备注。
- 模型请求无法稳定最小化。
- 导出结果无法追溯字段来源。

必须补充任务：

**Task 10A：实现字段确认结构和校验。**

要求：

- 支持我司库字段确认。
- 支持客户库字段确认。
- 至少识别商品编码、商品名称、品牌、规格、单位、备注。
- 商品名称字段缺失时不能开始对照。
- 字段确认结果必须写入任务元数据。

### E. 阻塞问题 5：缺少暂停、继续、停止任务

需求和 Demo 都确认了运行看板要有暂停、继续、停止。

原计划只在完成标准里提到了运行看板，但没有后端任务状态机。

必须补充任务：

**Task 12C：实现任务运行状态机。**

状态至少包括：

- `created`
- `running`
- `pausing`
- `paused`
- `stopping`
- `stopped`
- `completed`
- `failed`

要求：

- 暂停不是强杀当前处理中的单条，而是在安全检查点停下。
- 停止后不能导出“已完成正式结果”，只能导出当前诊断结果。
- 完成后才允许正式导出 Excel。

### F. 阻塞问题 6：第二轮回导写得太弱

原计划手工验收里有“开始第二轮”，但没有后端任务实现。

如果不补：

- 第一轮能导出，人工加工后无法回到系统。
- 003 的“逐轮减少人工”无法验证。

必须补充任务：

**Task 11A：实现人工加工 Excel 回导。**

要求：

- 必须校验系统任务行 ID。
- 人工已确认的结果不能被系统随意覆盖。
- 人工指定编码必须存在于最新我司库。
- 我司库更新后，第一轮未匹配项可以重新入大自然池。
- 回导冲突必须给中文提示，不能静默接受。

### G. 阻塞问题 7：Tauri 创建方式需要收敛

原计划写了：

```text

npm create tauri-app@latest desktop
```

这可能生成两个互相独立的前端壳，后续集成会乱。

必须修正：

`desktop` 不再另起一套 UI。

执行计划里每个任务都有 commit，这是好习惯。

### I. 调整后的真正执行顺序

修订后，建议执行顺序改为：

1. 提交当前文档基线。
2. Chunk 1：Python 后端工程骨架。
3. Chunk 2：003 核心数据结构。
4. Chunk 3：模型发令和大自然池。

也就是说：

**不要在后端任务状态、字段确认、回导和真实模型接口没打稳之前进入 UI 开发。**

### J. 自审结论

原执行计划的方向正确：

- 先后端核心引擎。
- 再 API。
- 再前端和 Tauri。
- TDD 粒度清楚。

但原计划低估了五个产品必需能力：

- 真实模型接入。
- 配置和 API Key 管理。
- SQLite 持久化。
- 字段确认。
- 第二轮回导和任务状态机。

这些必须作为正式开发任务补齐。
