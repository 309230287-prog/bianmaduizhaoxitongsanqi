# 商品编码对照系统 - 三期 3.1 业务流程文档 v0.1

- 日期：2026-04-25
- 阶段：三期 3.1 主线闭环
- 文档性质：业务流程文档，不是 UI 设计稿，不是技术方案
- 对应需求文档：`商品编码对照系统-三期需求文档-v0.2.md`

## 1. 文档目的

本文档用于说明三期 3.1 阶段用户如何完成一轮商品编码对照。

3.1 的目标不是一次性做完整系统。

3.1 的目标是先跑通主线闭环：

**初始化配置 -> 更新我司商品库 -> 新建对照任务 -> 对照进度看板 -> 导出 Excel -> 人工加工 -> 开始下一轮。**

本文档重点回答：

- 用户打开系统后先看到什么
- 首次使用时如何完成初始化配置
- 日常使用时如何进入业务流程
- 每一步用户做什么
- 每一步系统做什么
- 每一步失败时怎么提示
- 每一步产出什么

## 2. 3.1 流程总览

三期 3.1 分成两条流程。

### A. 首次启动和初始化配置流程

适用场景：

- 第一次打开系统
- 模型配置缺失
- API Key 缺失或失效
- 默认目录不存在
- 中文路径或文件名支持异常
- 用户主动进入设置页修改配置

目标：

**确保系统具备进行商品对照的基础配置，并让用户明确知道当前哪些能力可用。**

### B. 日常商品编码对照流程

适用场景：

- 系统配置正常
- 用户要处理一份客户商品库
- 用户要手工查询单条客户商品

目标：

**完成一轮真实商品编码对照，并导出业务人员能看懂的结果表。**

## 3. 首页入口流程

### 3.1 用户看到什么

用户打开系统后，应先进入首页工作台。

首页应清楚展示：

- 系统名称：商品编码对照系统
- 当前配置状态
- 当前模型状态
- 我司商品库状态
- 最近一次任务
- 主要操作入口

主要操作入口包括：

- 新建对照任务
- 继续历史任务 / 开始下一轮
- 更新我司商品库
- 查看历史任务
- 系统设置

### 3.2 系统自动检查什么

系统打开时自动检查：

- 是否存在基础配置
- 模型服务是否启用
- API Key 是否已配置
- 当前模型名称是否存在
- 默认数据目录是否可用
- 默认导出目录是否可用
- 日志目录是否可用
- 中文文件名和中文路径是否可用
- 是否已有我司商品库

### 3.3 首页状态提示

首页应使用中文状态提示。

示例：

- 配置正常，可以开始商品对照
- 模型未配置，无法进行智能候选和解释
- 尚未导入我司商品库，请先导入
- 默认导出目录不可用，请到设置中修正
- API Key 未配置，请先完成模型设置

### 3.4 首页分流规则

如果配置正常：

- 用户可以直接进入日常商品编码对照流程。

如果配置缺失或异常：

- 系统应提示用户进入初始化配置流程。
- 系统不应悄悄进入模型判断流程。

如果只是模型未配置：

- 系统应明确提示智能候选、中文解释等能力不可用。
- 第一版是否允许无模型继续走基础流程，由后续技术方案决定。
- 在 3.1 流程文档中，默认按“模型未配置则不能进行智能对照”处理。

## 4. A 流程：首次启动和初始化配置

### A1. 进入初始化配置页

触发方式：

- 首次打开系统自动进入
- 首页提示配置异常后点击进入
- 用户主动点击系统设置

用户看到：

- 当前配置总览
- 哪些配置已完成
- 哪些配置缺失
- 下一步应配置什么

系统显示：

- 模型配置状态
- 数据目录状态
- 导出目录状态
- 日志目录状态
- 中文路径检查状态

产出：

- 初始化配置检查结果

### A2. 配置模型服务

用户需要配置：

- 是否启用模型服务
- 模型提供方
- Base URL
- API Key 来源或录入方式
- 模型名称
- 请求超时
- 失败重试次数

系统要求：

- API Key 不能写入源码。
- API Key 不能提交到仓库。
- API Key 显示时应脱敏。
- 配置保存后应提示保存成功或失败。

系统检查：

- Base URL 是否为空
- API Key 是否为空
- 模型名称是否为空
- 配置格式是否明显错误

异常提示：

- API Key 未填写
- Base URL 未填写
- 模型名称未填写
- 配置保存失败
- 模型连接测试失败

产出：

- 模型配置记录
- 模型可用性状态

### A3. 测试模型连接

用户操作：

- 点击测试连接

系统操作：

- 使用当前配置发起最小测试请求
- 返回连接是否成功
- 显示失败原因

成功提示：

- 模型连接成功，可以进行智能对照

失败提示：

- 模型连接失败，请检查 API Key、Base URL 或网络

注意：

- 测试连接不应发送客户商品库真实数据。
- 测试连接只验证模型服务是否可用。

产出：

- 模型连接测试结果

### A4. 配置默认目录

用户需要确认：

- 默认数据目录
- 默认导出目录
- 日志保存目录

系统检查：

- 目录是否存在
- 是否可读
- 是否可写
- 是否支持中文路径

异常提示：

- 目录不存在
- 目录不可写
- 中文路径测试失败

产出：

- 默认目录配置
- 目录可用性状态

### A5. 初始化完成

完成条件：

- 必要模型配置已填写
- 模型连接测试通过
- 默认目录可用
- 中文路径检查通过

系统提示：

- 初始化完成，可以开始商品对照

用户下一步：

- 返回首页
- 进入日常商品编码对照流程

## 5. B 流程：日常商品编码对照

### B1. 选择业务入口

用户从首页选择：

- 新建对照任务
- 继续历史任务 / 开始下一轮
- 更新我司商品库

系统前置检查：

- 配置是否有效
- 模型是否可用
- 是否已有我司商品库

如果没有我司商品库：

- 系统提示先导入我司商品库。

如果模型不可用：

- 系统提示智能对照不可用。

### B2. 更新我司商品库

我司商品库是系统基础资料。

它不属于每次客户对照任务的必经步骤。

适用场景：

- 第一次使用
- 我司商品库发生更新
- 用户主动替换我司商品库

用户操作：

- 选择我司商品库 Excel
- 上传或导入

系统读取：

- 工作表名称
- 表头
- 样例行
- 数据行数
- 重复列
- 空白列

系统提示：

- 导入成功
- 发现重复列
- 发现空白列
- 缺少我司商品编码
- 缺少我司商品名称

用户确认：

- 哪一列是我司商品编码
- 哪一列是我司商品名称
- 哪些列是品牌、规格、单位、分类、别名、描述
- 哪些列不参与判断

产出：

- 我司商品库记录
- 我司字段含义确认结果

### B3. 上传客户商品库

B3、B4、B5、B6 在界面上合并为同一个“新建对照任务”页面。

上传客户商品库只是新建任务的第一步。

本步只展示系统读到的列名、样例和异常提醒，不要求用户在这里完成复杂字段判断。

用户操作：

- 选择客户商品库 Excel
- 上传或导入

系统读取：

- 工作表名称
- 表头
- 样例行
- 数据行数
- 重复列
- 空白列
- 明显异常字段

系统提示：

- 导入成功
- 发现重复商品名称列
- 发现空白列
- 商品名称字段未确认
- 规格字段缺失，可能影响包装和容量判断
- 单位字段缺失，可能影响结算单位判断

系统预判：

- 商品名称字段
- 客户编号字段
- 品牌字段
- 规格字段
- 单位字段
- 类别字段
- 备注字段
- 其他补充字段
- 不参与判断字段

产出：

- 客户商品库记录
- 客户字段初步预判结果

### B4. 手工输入单条客户商品

手工输入和客户 Excel 上传属于同一个“新建对照任务”页面的两种输入方式。

适用场景：

- 用户临时查询一条商品
- 用户没有完整客户 Excel
- 用户想测试某条商品对照

用户输入：

- 商品名称
- 品牌
- 规格
- 单位
- 类别
- 备注
- 客户编号
- 其他补充信息

最低要求：

- 商品名称不能为空

系统处理：

- 将手工输入视为一条客户商品记录
- 进入同一套字段确认、开始对照、导出 Excel 流程

产出：

- 单条客户商品记录

### B5. 字段确认完成检查

字段确认是“新建对照任务”页面的第二步。

系统可以预判字段含义，但不能完全黑箱跳过人工确认。

系统检查：

- 客户商品名称是否确认
- 我司商品编码是否确认
- 我司商品名称是否确认
- 强建议字段是否缺失

如果必需字段缺失：

- 系统阻止继续，并提示必须补齐。

如果强建议字段缺失：

- 系统允许继续，但提示会影响自动落码等级。

产出：

- 字段确认通过或失败

### B6. 开始第一轮对照

开始第一轮对照是“新建对照任务”页面的第三步。

用户操作：

- 在字段确认通过后，点击开始第一轮对照

页面跳转：

- 点击后进入对照进度看板。

系统操作：

- 再次检查我司商品库是否可用
- 再次检查客户商品库或手工输入记录是否可用
- 再次检查必需字段是否已经确认
- 再次检查模型服务是否可用
- 读取客户商品记录
- 读取我司商品库
- 根据客户整行信息生成我司候选
- 为每条客户商品保留候选来源说明

候选来源可能包括：

- 名称相似
- 核心品名一致
- 品牌一致
- 规格一致
- 单位一致
- 分类接近
- 历史确认
- 业务等价
- 人工曾经选择

异常情况：

- 字段确认未完成，不允许开始
- 模型不可用，不允许静默生成智能结果
- 没有候选
- 候选过多
- 候选都存在核心冲突

产出：

- 第一轮对照任务记录
- 第一轮运行进度
- 每条客户商品的候选列表
- 候选来源摘要

### B7. 系统内部生成候选、证据对齐和中文解释

系统对客户记录和候选进行证据对齐。

本步骤在 3.1 中不做单独候选解释页面。

解释、风险和备选候选先写入导出 Excel。

系统输出：

- 推荐我司商品
- 备选候选
- 对上的信息
- 没对上的信息
- 风险提示
- 推荐理由
- 五档状态

五档状态包括：

- 自动落码
- 自动落码但有表达差异
- 建议落码待确认
- 必须人工审核
- 未找到可靠匹配

系统原则：

- 不能只输出一个编码。
- 不能把必须人工审核伪装成自动落码。
- 不能把未找到可靠匹配伪装成确定编码。

产出：

- 对照结果草稿
- 写入 Excel 的中文推荐理由
- 写入 Excel 的证据对齐摘要
- 写入 Excel 的风险提示
- 写入 Excel 的备选候选

### B8. 对照进度看板

用户点击开始第一轮对照后，进入对照进度看板。

看板展示：

- 当前任务名称
- 当前轮次，例如第 1 轮、第 2 轮
- 当前状态，例如运行中、已暂停、已停止、本轮已完成
- 我司商品库总数
- 客户商品库总数
- 已完成数量
- 自动落码无风险数量
- 建议落码需复核数量
- 必须人工干预数量
- 未找到可靠匹配数量
- 进度条

看板提供：

- 暂停
- 继续
- 停止
- 导出 Excel

导出规则：

- 运行中不能导出正式结果。
- 暂停中不能导出正式结果。
- 停止后本轮不算完整完成，不能导出正式结果。
- 只有本轮已完成后，导出 Excel 按钮才可点击。

3.1 中统计数字框只展示数量，不进入页面明细。

页面明细表、候选展开、页面人工审核放到后续版本。

产出：

- 第一轮运行状态
- 分类统计结果
- 可导出的 Excel 结果

### B9. Excel 人工加工

3.1 不在系统页面中做完整人工审核工作台。

人工审核先通过导出的 Excel 完成。

用户在 Excel 中可以：

- 确认系统推荐结果
- 修改我司商品编码
- 标记无匹配
- 标记需要新增我司商品
- 填写人工审核备注

如果发现我司商品库缺商品，用户应先补全我司商品库。

补全后回到系统更新我司商品库。

产出：

- 人工加工后的 Excel
- 可能更新后的我司商品库

### B10. 导出 Excel 和开始下一轮

用户操作：

- 本轮完成后，点击导出 Excel
- 选择导出位置

系统操作：

- 基于客户原始 Excel 生成新文件
- 不覆盖原文件
- 保留客户原始所有列
- 尽量保持客户原始列顺序和行顺序
- 在客户原始列后面追加中文结果列
- 不应导出一张只包含结果字段的新表
- 生成多工作表 Excel，避免总表过宽

工作表建议：

- 对照结果总表
- 详细证据表
- 统计汇总表

对照结果总表要求：

- 保留客户原始列
- 追加少量关键结果列
- 包含系统任务行ID
- 包含查看详细证据的内部链接

追加结果列建议包括：

- 系统任务行ID
- 原始行号
- 对照状态
- 我司商品编码
- 我司商品名称
- 是否需要人工审核
- 推荐理由简述
- 风险提示简述
- 查看详细证据
- 人工确认结果
- 人工审核备注

详细证据表建议包括：

- 系统任务行ID
- 原始行号
- 客户商品名称
- 推荐我司商品
- 证据对齐摘要
- 对上的信息
- 没对上的信息
- 风险详情
- 备选候选 1
- 备选候选 2
- 备选候选 3
- 返回总表

统计汇总表建议包括：

- 当前任务名称
- 当前轮次
- 我司商品库总数
- 客户商品库总数
- 自动落码无风险数量
- 建议落码需复核数量
- 必须人工干预数量
- 未找到可靠匹配数量
- 本轮开始和完成时间
- 使用模型
- 我司商品库版本或更新时间

内部链接要求：

- 总表中“查看详细证据”应能跳到详细证据表对应行。
- 详细证据表中“返回总表”应能跳回总表对应行。

第二轮入口：

- 首页提供“继续历史任务 / 开始下一轮”入口。
- 用户上传人工加工后的 Excel。
- 如果我司商品库有更新，先更新我司商品库。
- 然后点击开始第 2 轮对照。

第二轮处理规则：

- 人工已确认的，不要被系统随意覆盖。
- 人工指定我司编码的，系统要校验编码是否存在于最新我司库。
- 第一轮未匹配或需新增的，如果我司库更新后已有对应商品，应重新对照。
- 如果人工结果和当前我司库冲突，应提示风险，不应静默接受。

异常提示：

- 导出目录不可写
- 文件被占用
- 导出失败

产出：

- 编码对照结果 Excel
- 人工加工后的下一轮输入文件

## 6. 异常和中断流程

### 6.1 模型不可用

触发场景：

- API Key 缺失
- API Key 失效
- Base URL 错误
- 网络不可用
- 模型服务超时

系统处理：

- 明确提示模型不可用。
- 不应静默生成模型结果。
- 不应伪造智能判断。
- 引导用户进入设置页修正。

### 6.2 文件读取失败

触发场景：

- Excel 文件损坏
- 文件格式不支持
- 文件被占用
- 表头无法识别

系统处理：

- 明确提示读取失败原因。
- 不应生成空任务。

### 6.3 字段确认不完整

触发场景：

- 客户商品名称未确认
- 我司商品编码未确认
- 我司商品名称未确认

系统处理：

- 阻止继续对照。
- 提示必须补齐字段。

### 6.4 导出失败

触发场景：

- 导出目录不存在
- 导出目录不可写
- 文件被占用

系统处理：

- 提示失败原因。
- 允许用户重新选择导出目录。

## 7. 3.1 不做什么

3.1 不做：

- 完整记忆系统
- 复杂审核流
- 多人协同
- 权限体系
- 高级统计
- 大规模自动学习
- 模型精调
- 复杂模型管理中心
- 让记忆直接决定自动落码
- 页面明细列表
- 页面候选展开
- 页面人工审核工作台

3.1 只做：

**跑完一轮，导出业务能处理的 Excel，并支持人工加工后进入下一轮。**

## 8. 3.1 验收标准

3.1 至少应满足：

- 首次打开能看到配置状态。
- 配置缺失时能引导用户完成初始化。
- 配置正常时能进入首页工作台。
- 能导入我司商品库。
- 能将客户库上传、手工输入、字段确认、开始对照合并在新建对照任务中完成。
- 字段确认通过后，用户能明确点击开始第一轮对照。
- 点击开始后能进入对照进度看板。
- 对照进度看板能显示当前轮次、运行状态、统计数字和进度条。
- 对照进度看板支持暂停、继续、停止。
- 本轮未完成时不能导出正式 Excel。
- 必需字段缺失时能阻止继续。
- 强建议字段缺失时能给出风险提示。
- 能生成候选或说明无候选原因。
- 能在导出 Excel 中输出中文解释和风险提示。
- 能输出五档中文状态。
- 能导出多工作表编码对照结果 Excel。
- Excel 总表能跳转到详细证据表。
- 人工加工后的 Excel 能作为下一轮输入。
- 不覆盖原始 Excel。
- 模型不可用时不伪造智能结果。
