# 商品智能匹配系统需求文档

- 版本：v0.1
- 日期：2026-03-24
- 状态：规划中

## 1. 项目目标

本项目要解决的是“客户商品库”与“我司商品库”之间的商品对照问题。

当前痛点：
- 客户和我司 Excel 字段名不统一
- 同一商品名称写法不统一
- 人工逐条对照效率低、周期长、容易错
- 结果缺少稳定沉淀，后续难复用

项目目标：
- 让业务人员可以在 Windows 客户端中上传两份 Excel
- 通过字段对照表确定两份表中各列的业务含义
- 由系统自动完成商品候选匹配、结果标记和回写
- 对不确定结果进行人工审核
- 最终导出新的 Excel 结果文件

## 2. 产品定位

本产品定位为：

- Windows 本地客户端
- 单机可安装使用
- 本地运行、离线优先
- AI 作为可选增强能力，不作为基础运行前提

不做成第一阶段目标的内容：
- 公网 SaaS 平台
- 多租户复杂权限系统
- 必须联网才能工作的产品

## 3. 使用对象

主要用户：
- 采购人员
- 销售支持人员
- 商品资料维护人员
- 需要做客户商品对照的内部运营人员

## 4. 核心业务流程

系统核心流程如下：

1. 上传我司商品库 Excel
2. 上传客户商品库 Excel
3. 系统读取两份 Excel 的表头
4. 在页面上展示字段对照表
5. 用户分别为“我司商品库列名”和“客户商品库列名”选择对应关系
6. 用户确认字段对照后启动匹配
7. 系统执行商品匹配
8. 系统在客户原始表格后追加我司匹配结果列
9. 系统用明显标识区分“已匹配、建议匹配、未匹配”
10. 用户可查看、审核、导出结果 Excel

## 5. 输入方式

### 5.1 上传文件

系统第一步要求上传两份 Excel：

- 我司商品库
- 客户商品库

支持格式：
- `.xlsx`
- `.xls`

第一版以 `.xlsx` 为主。

### 5.2 字段对照表

上传完成后，系统展示固定结构的字段对照表。

字段对照表包含三列：
- 字段名称
- 我司商品库（列名）
- 客户商品库（列名）

字段名称固定为以下 6 项：
- 商品编码
- 商品名称
- 规格
- 品牌
- 单位
- 分类

交互规则：
- 每一行都是一个标准业务字段
- 用户在“我司商品库”列中选择该字段对应的我司 Excel 列名
- 用户在“客户商品库”列中选择该字段对应的客户 Excel 列名
- 若某个字段不存在，可允许暂不选择，但系统要提示影响

### 5.3 字段作用说明

- 商品编码：用于标识、回写、追溯、历史复用
- 商品名称：核心匹配字段
- 规格：核心匹配字段
- 品牌：核心匹配字段
- 单位：核心匹配字段
- 分类：辅助匹配与候选筛选字段

说明：
- 商品编码不作为跨表“是否同物”的核心判断依据
- 真正参与主要匹配判断的核心因素为：
  - 商品名称
  - 品牌
  - 规格
  - 单位
  - 分类

## 6. 商品匹配原则

### 6.1 总体原则

系统不直接“瞎猜”，而是尽量模拟成熟采购人员的判断顺序：

1. 先看名称，判断这到底是什么商品
2. 再看品牌，确认是不是同一品牌
3. 再看规格，确认是不是同一规格
4. 再看单位，确认是不是同一销售单位或包装层级
5. 再结合分类辅助确认
6. 若仍不确定，则给出建议匹配，由人工审核

### 6.2 名称优先原则

名称是第一判断入口。

例如：
- “海天酱油”

系统应优先从名称中识别：
- 商品主词：酱油
- 品牌词：海天

也就是说，系统首先要判断“这是什么商品”，再判断“它是谁家的”，而不是先死看分类。

### 6.3 匹配顺序

推荐匹配顺序：

1. 从名称中识别商品主词、品牌词、规格词、包装词
2. 先按商品主词和分类缩小候选范围
3. 再比较品牌
4. 再比较规格
5. 再比较单位
6. 最后结合分类和历史匹配结果做辅助判断

### 6.4 AI 的作用

AI 或其他智能工具不负责无条件拍板，而负责：

- 理解商品名称
- 识别别名、简称、口语写法
- 拆解名称中的品牌、规格、包装信息
- 对模糊候选做排序
- 给出匹配原因说明

系统基础原则为：

- 规则优先
- AI 增强
- 人工兜底
- 历史结果沉淀复用

## 7. 匹配逻辑要求

### 7.1 历史匹配优先

若系统中已经存在历史确认关系，则优先复用。

可复用对象包括：
- 客户商品编码 -> 我司商品编码
- 已确认的字段组合 -> 已确认商品

### 7.2 候选召回

系统不应直接在全库中盲目比较，而应先召回候选。

候选缩小方式包括：
- 商品名称主词
- 分类
- 品牌
- 常见别名映射

### 7.3 核心判断逻辑

建议采用以下业务判断逻辑：

- 名称：判断是不是同类商品、同一商品表达
- 品牌：不一致时高风险，通常不能自动确认
- 规格：核心数字和单位冲突时，通常不能自动确认
- 单位：包装层级不一致时，通常不能自动确认
- 分类：用于辅助筛选和辅助判断

### 7.4 结果分级

系统输出建议至少包含以下状态：

- 历史命中
- 自动匹配
- 建议匹配
- 未匹配
- 数据不足 / 无法判断

含义建议：

- 历史命中：以前确认过，直接复用
- 自动匹配：系统判断信号充足，可直接匹配
- 建议匹配：系统给出候选，需要人工确认
- 未匹配：没有找到可接受候选
- 数据不足 / 无法判断：字段缺失或信息冲突

## 8. 输出方式

### 8.1 输出原则

输出文件以客户原始 Excel 为主，不覆盖原始文件。

系统应生成一个新的结果 Excel，例如：
- `客户商品库_匹配结果.xlsx`

### 8.2 输出结构

在客户原始表格后追加我司匹配结果列。

建议追加列包括：
- 匹配状态
- 我司商品编码
- 我司商品名称
- 我司品牌
- 我司规格
- 我司单位
- 我司分类
- 匹配说明
- 审核状态
- 审核备注

### 8.3 视觉标识

结果 Excel 中需要有明显标识：

- 绿色：已匹配 / 历史命中 / 自动匹配
- 黄色：建议匹配 / 待人工确认
- 红色：未匹配
- 灰色：数据不足 / 无法判断

## 9. 客户端形态

### 9.1 部署方式

系统应以 Windows 客户端形式提供。

目标体验：
- 像普通 Windows 软件一样安装
- 安装后可直接打开使用
- 不依赖服务器即可进行基础工作

### 9.2 运行方式

基础能力默认本地运行：
- Excel 读取
- 字段映射
- 匹配执行
- 结果导出

### 9.3 AI 配置方式

若启用大模型增强能力，需在软件设置页提供配置项：

- API Base URL
- API Key
- 模型名称
- 是否启用 AI 辅助匹配

AI 设计原则：
- AI 为可选增强项
- 没有 API 时，系统仍应可运行基础规则匹配

## 10. MVP 范围

第一版建议只做以下内容：

- 双 Excel 上传
- 固定字段对照表
- 基础字段校验
- 名称优先的商品匹配
- 品牌/规格/单位规则校验
- 候选建议输出
- 匹配结果回写客户 Excel
- 颜色标识结果
- 人工审核字段
- Windows 本地运行
- AI 配置入口

第一版先不做：

- 多人在线协作
- 复杂组织权限
- 云端中心化数据平台
- 复杂流程审批
- 自动学习后无审核直接放行

## 11. 非功能要求

### 11.1 性能

第一版性能目标建议：
- 4000-5000 条客户商品可在可接受时间内完成匹配
- 页面交互流畅
- 导出 Excel 稳定

### 11.2 安全

- 客户数据默认不出本地
- AI 调用需明确由用户主动配置
- 敏感商品数据不默认上传外部服务

### 11.3 可维护性

- 字段对照规则可复用
- 匹配结果可沉淀
- 历史人工审核结果可复用

## 12. 匹配规则概要

为避免需求文档过度膨胀，完整匹配细则单独维护在配套规则文档中。
本需求文档只保留业务层面的概要原则。

概要原则如下：
- 系统不直接拿整条商品名称硬比，而是先做标准化拆分
- 我司商品库保留原始字段，同时额外生成标准字段
- 客户商品库通过字段对照后，也整理成同一套标准字段
- 标准字段以商品名称、品牌、规格、单位、分类为核心
- 匹配主顺序为：先看商品名称，再看品牌、规格、单位，分类做辅助
- 品牌识别依赖品牌词库，不靠名称位置瞎猜
- 规格优先提取，规格明确冲突时不能自动匹配
- 输出结果必须分级，不能全部直接自动确认
- 人工审核结果和历史匹配关系需要沉淀复用
- 规则必须支持商品库持续更新后重复执行

## 13. 当前已确认结论

- 输入方式：双 Excel 上传
- 字段处理方式：固定字段对照表
- 标准字段：商品编码、商品名称、规格、品牌、单位、分类
- 匹配原则：名称优先，再结合品牌、规格、单位、分类
- 输出方式：客户表后追加我司信息列，并导出新 Excel
- 产品形态：Windows 客户端
- AI 角色：可选增强，不是强依赖

## 14. 仍需后续确认的问题

- 自动匹配与建议匹配的具体判定阈值
- 品牌缺失时是否允许降级匹配
- 分类在第一版中是强辅助还是弱辅助
- 历史匹配关系的保存方式与复用方式
- 审核界面是第一版就做完整，还是先以 Excel 回写为主
