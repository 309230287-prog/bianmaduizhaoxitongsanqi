# Task Brief

## Name

商品编码对照二期多智能体并行推进

## Type

OMC plan/build orchestration

## Background

项目当前方向已经由二期需求文档、实施路书和技术执行规格冻结。

二期不是一期匹配产品升级。大模型负责商品语义理解、证据对齐、风险判断和解释；程序负责 Excel、上下文拼装、调用、保存、审核、导出和留痕。

当前允许复用一期 FastAPI/Jinja2、后台任务、日志、下载等工具性基础设施，但不允许把一期匹配逻辑、一期结果分级或一期自动落码策略包装成二期语义判断。

当前已完成：`src/product_matcher_phase2/` 独立二期包、30 条黄金样本、10 条试跑输入、候选池覆盖率报告、DeepSeek 连接测试、产品内二期语义试跑控制台骨架。

当前关键事实：DeepSeek 10 条脚本级试跑全部未通过 JSON/schema 校验，不能视为模型验证成功。

当前工程风险：`D:\编码对照项目\编码对照项目_主线` 不是独立 git 仓库，父级仓库 `D:\编码对照项目` 很脏。继续并行前必须建立干净项目边界。

## Goal

用“总管 + 多智能体并行”的方式推进二期，先建立干净的项目边界、分支/worktree 规范和 agent 分工，再继续实现二期语义验证链路。

## Boundaries

- 不推 GitHub。
- 不把一期 `/match` 或 `/export` 宣称为二期正式链路。
- 不做完整客户库批量自动落码。
- 不把 DeepSeek 试跑失败包装成成功。
- 不在未通过 JSON/schema 验证前声称模型能力通过。
- 实现 agent 必须有明确文件所有权，不重叠写同一文件。
- 总管负责集成、冲突处理、验收和最终交接。

## Acceptance Checks

- 项目有清晰的本地 git/worktree 边界。
- OMC 任务中记录 agent 架构和职责。
- 至少一个只读审查 agent 和一个实现/诊断 agent 并行运行。
- 合并前运行全量测试并记录真实结果。
- 最终交接说明包含：完成项、未完成项、风险、下一步。

## Notes

下一步优先修正模型输出契约和 JSON/schema 稳定性，再扩大到 10 条黄金样本产品内试跑。
